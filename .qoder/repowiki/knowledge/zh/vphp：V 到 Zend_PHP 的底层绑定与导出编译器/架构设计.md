模块按职责划分为 7 个子目录，形成「Zend C 层 → 值模型层 → 语义包装层 → 导出编译器」的分层边界：
- `zend/`：最底层，通过 `C.` 直接调用 Zend C API（如 `zend_execute_data`、`zval`、`class_entry`），并封装异常、输出、内存分配、request 启动/关闭等运行时入口（见 `runtime.v`）。
- `bridge/`：纯 C 片段（`.inc.c` + `compat.h`），作为 V 与 Zend C 之间的 FFI 薄壳，被 `zend/` 和根目录 C 文件引用。
- `zval/`：围绕 `ZVal` 的结构化操作（标量、数组、对象、资源、迭代器、引用、foreach、include 等），是上层语义包装的基础。
- `object/`：对象绑定与生命周期（handle、handlers、lifecycle、property、roots、zval），配合 `scope/` 的 autorelease 与 request scope 实现显式所有权。
- `execute/`：执行上下文门面（args/context/handle），把 `Context` 暴露给导出函数签名。
- 根目录约 80+ `.v` 文件构成「值模型层」：`php_*_type.v` 定义 `PhpValue`/`PhpInt`/`PhpString`/`PhpArray`/`PhpObject` 等语义包装；`zbox_*` 系列提供 `RequestBorrowedZBox`/`RequestOwnedZBox`/`PersistentOwnedZBox` 等生命周期盒；`php_value_read.v`、`php_object_call.v`、`php_function.v` 等提供从 V 调 PHP 的统一 API。
- `compiler/`：独立的 V 子模块，遵循 AST→repr→linker→builder→emitter 管线（见 `entry.v` 的 `compile()` 两阶段扫描 + linker 链接），产出 C/V glue 代码供扩展编译期生成。
依赖方向严格自底向上：`compiler` 仅依赖 V 标准库与自身子包；运行时层 `zend → bridge → zval/object/scope → 语义包装`，不允许反向依赖。
